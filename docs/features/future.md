# Future Topics

Только вопросы, которые нужно решить перед включением соответствующей функции. Текущие правила остаются в предметных контрактах, задачи и проверки первого билда — в [MVP roadmap](../roadmap-mvp.md).

| Тема | Что сохранить |
|---|---|
| Доставка приложения | Уточнить поддерживаемые версии Windows/Linux и проверить установку, обновление и блокировку данных на обеих ОС. |
| Экспорт и перенос | Разделить выдачу выбранных результатов и полный перенос остановленной установки с БД, checkpoints, файлами и версиями ресурсов без двух одновременно пишущих копий. |
| Резервное копирование | До production согласовать допустимую потерю данных, время восстановления и сроки хранения копий, затем проверить реальное восстановление. |
| Fork | [Дочерний запуск с выбранного этапа](../hilp/fork.md): точные upstream results переиспользуются, новые проходят свои HITL; родитель независим. Дерево запусков после MVP, без merge и автоматического сравнения. |
| Общий чат | При расширении node discussion определить редактирование, удаление, частичные ответы и сроки истории, сохраняя связь сообщений с точными версиями. |
| Совместная работа | Перед sharing определить роли и отзыв доступа, проверяя права как при поиске, так и при выдаче конкретного результата. |
| Wiki и личный вкус | Определить редактор, импорт и явную публикацию версии владельцем без обязательного второго reviewer, автоматического изменения вкуса или раскрытия private материалов. |
| Права на источники | Отзыв разрешения должен распространяться на производные знания, индексы и подготовленный контекст, а правила очистки — учитывать общие медиа и ограниченный аудит. |
| Поиск | Добавлять vectors только после сравнения с прямыми ссылками и полнотекстовым поиском на проверочном наборе по качеству, утечкам и стоимости. |
| Аккаунты | Перед hosted activation уточнить подтверждение почты, восстановление и срок сессий при принятом Supabase email/password; локальная регистрация не загружает проект. |
| Удалённые задания | До включения сервиса проверить авторизацию, условия провайдера, поиск заказа после потери ответа и импорт выбранных файлов без переноса владения проектом исполнителю. |
| Загрузки и очистка | Определить технические ограничения размера, времени и параллельности и удаление непривязанных загрузок без гонки с прикреплением к живому заказу. |
| Сроки хранения | Перед удалением service identities определить retention/tombstones, чтобы старый ключ не создавал новый платный заказ; сроки outputs и входных payloads остаются раздельными. |
| Кредиты и потерянные ответы | До включения сервисных кредитов проверить повторные начисления, резервы и списания, а потерянный текст учитывать по подтверждённому usage без автоматической повторной генерации; детали — в [billing](../database/credits-billing.md). |
| Финальные лимиты и оплата | Дневные бесплатные лимиты с корректным часовым поясом, реальные платежи и подписки вводить отдельным этапом с проверкой расчётов и условий сервиса. |

Наличие темы здесь не откладывает обязательные для активного пути проверки доступа, идемпотентности и сохранности; старые Q-идентификаторы и дубли решённых вопросов больше не являются checklist.
