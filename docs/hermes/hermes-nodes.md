# Этапы и данные

**Статус: продуктовые роли, не API или исполняемый формат нод.** MVP использует готовый небольшой маршрут; ручная сборка цепочек — #future.

## Basic nodes

| Роль | Что делает | Что показываем |
|---|---|---|
| Agent | Получает ограниченное задание /goal, skills и выбранный контекст | Задание, состояние, текст/материалы, при возможности разговор |
| Tool | Выполняет конкретное действие без обязательного рассуждения модели | Параметры, заказ, прогресс, результат или ошибка |
| HITL | Фиксирует выбор или принятие конкретного материала | Что именно выбрано и что разрешено дальше | **хз** если нужна отдельная нода `hitl`, можно этап апрува вставить в базовую ноду, и например сделать переключатель на auto/manual.

Эти роли не требуют трёх новых runtime-классов. Hermes должен предложить их отображение на существующие механизмы. `SKILL.md` — инструкция специалисту, не готовая исполняемая нода.

## Вход и результат

Вход: задание /goal, выбранные версии материалов, нужные wiki/references и параметры. Общую историю проекта читаем по необходимости, а не вставляем весь файл каждому специалисту.

Для передачи следующему шагу нужен проверяемый результат: например, раскадровщик возвращает список `frames` с описаниями и ссылками на входы. Медиа и длинные prompts хранятся отдельно. Для инструмента результатом может быть сохранённый файл с параметрами генерации, а не LLM JSON.

Связь передаёт выбранные данные. Картинка или заметка на доске не включается в context автоматически. Константы возможны как параметры проекта из brief.json; отдельный универсальный язык выражений пока не нужен.

## `/goal`: вопрос, а не формула

Нужно выяснить, можно ли задать специалисту цель и проверяемое завершение штатными средствами Hermes, включая `/goal`. Нельзя заранее приравнивать `/goal` к ноде, durable checkpoint или согласованию автором. Успешный ответ агента сам по себе не открывает следующий этап, если требуется выбор человека.
