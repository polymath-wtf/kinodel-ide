# Kinodel для Hermes — пакет препродакшна

**Статус:** продуктовые требования и предлагаемая native-архитектура для реализации в целевом Hermes. Это не проверенный деплой и не миграция backend текущего Kinodel. Снимок Hermes docs не привязан к версии/commit; его утверждения нужно сверить с установленной версией.

## Продукт

Kinodel — компактное творческое рабочее пространство на React: dashboard этапов, раскадровка, библиотека материалов и детали выбранной ноды. Автор видит результат каждого шага, выбирает дубли и управляет правками, а не пересказывает весь проект в одном бесконечном чате.

Hermes исполняет задания и владеет их жизненным циклом. Четыре специалиста отвечают за своё ремесло, инструменты создают медиа, человек принимает творческое направление. Producer — **необязательный помощник** для брифа и обратной связи; Montage — детерминированный инструмент, не пятый творческий агент.

## Фиксированный cinematic MVP

```text
brief (ввод автора, при желании с Producer)
→ Storytell → утверждение story
→ Wardrobe → anchor generation → утверждение anchors
→ Storyboard → frame generation → утверждение frames
→ Filmmaker → video generation → утверждение videos
→ Montage → технически проверенный немой final MP4
```

MVP готов только после **полного фильма**, не на результате из одних текстов/картинок. Число кадров и конкретные провайдеры выбираются для проверочного проекта, а не становятся универсальным ограничением продукта. Маршрут фиксирован: без конструктора нод/связей. Нода может показывать агента, инструмент или review; не каждая нода — отдельный child instance.

## Путь автора

1. Создать проект: идея, формат, длительность кадров, настройки производства, выбранные персонажи и референсы.
2. Отправить явный brief напрямую или подготовить его с Producer. Обязательного чата и отдельного brief approval нет.
3. Смотреть этапы, их точные входы, подготовленный контекст, задания и результаты в одном workspace.
4. На четырёх review выбрать и утвердить конкретную ревизию story или полный совместимый набор медиа. Планы доступны для чтения, но не имеют дополнительных обязательных approval gates.
5. Запросить смысловую правку у владельца этапа либо поменять prompt/settings и отправить явный manual render **без обязательного LLM**. Старый результат остаётся в библиотеке, новый не утверждается автоматически.
6. Вернуться после reload/restart, открыть сохранённые originals и продолжить только доступное действие. Неизвестный исход платного заказа требует сверки, а не слепого повторения.

Правка уже утверждённого предка не запускает каскад автоматически и не делает старые downstream-медиа «соответствующими» новой истории. MVP создаёт новую production/revision lineage; прежняя история и результаты сохраняются отдельно.
