## Contract

The adapter owns one authoritative versioned workflow registry, semantic-to-node mappings, readiness, input materialization, submission/reconciliation and verified output import. Do not duplicate aliases in Python and JSON. Workflow version participates in the job fingerprint; secrets, raw workflows, queue IDs and logs stay out of creative artifacts. Health checks use real readiness endpoints without generating paid content; provider paths/URLs are not durable asset identities.

## Local Connection

Browser talks only to the local Kinodel origin; Python worker calls ComfyUI over HTTP or HTTPS and imports originals into managed storage. Same-machine loopback HTTP needs no public HTTPS tunnel or direct browser access/CORS change. One installed `httpx` client supports both schemes; HTTPS verifies certificate/hostname, with an explicit trusted CA if needed. Disable environment proxy routing for loopback.

Implemented trusted settings: `COMFYUI_LOCAL_ENDPOINT` defaults to `http://127.0.0.1:8188`; `COMFYUI_SERVER_ENDPOINT` is an explicitly selected alternative native connection, possibly a tunnel to that same server. `COMFYUI_CONNECTION=local|server` defaults to local; preflight may explicitly select either configured connection. Optional `COMFYUI_AUTH_TOKEN` supplies Bearer auth separately from the URL; absolute `COMFYUI_CA_FILE` builds a verifying SSL context. Explicit launcher env-file loading preserves exported environment and permits empty optional ComfyUI settings; there is no auto-loading. Never switch after an outage; future prepared jobs must pin connection/endpoint identity. HTTPS is not a signal to select Comfy Cloud routes/auth.

`backend/comfyui.py` exposes a bounded read-only preflight, independent of application startup and saved-project reads. Guarded `GET /api/comfyui/workflows` lists available candidate basenames from the single registry; `GET /api/comfyui/preflight` accepts optional `connection` and a declared `workflow` basename. The typed report includes reachable/dependencies_ready, workflow/endpoint digests, registry ID/version/digest, preparation_enabled/graph_ready, reported versions/GPU/VRAM, used classes/schema digests, exact selected model availability and explicit unknowns. Native V1/V3 model-loader combos are inventory evidence; `/models` and `/models/{folder}` are used when a combo is unavailable. Special loaders without verified inventory block dependency readiness. Unreported custom versions are null/advisory. Report data excludes raw schemas/responses/argv, credentials and private absolute paths. Inventory readiness and graph validation are separate; production generation profiles remain pending.

Calls use only native GET, connect 5 s / request 15 s / total 60 s, a 16 MiB JSON response cap, `trust_env=False`, verified HTTPS and no redirects/retries/fallback. CLI `python -m backend.comfyui --env-file .env --connection local` (or `server`) returns JSON and nonzero status on dependency failure; default candidate is txt2img Krea2. Live HTTP/HTTPS dependency evidence and the offline saved-project regression are recorded in [step 1](../roadmap-comfyui.md#1-подключение-и-read-only-preflight). Health/dependency presence does not prove execution, dimensions, model compatibility or VRAM sufficiency.

A hosted Kinodel backend cannot reach a user's machine through its own loopback address. A future hosted-to-local bridge is a separate transport activation, not required for the local Windows pilot.

## Profile Selection

This is a deterministic adapter rule, not an LLM provider choice or a claim that working profiles are registered. A registered generation profile binds its stable ID and immutable version/digest to provider, job kind, workflow ID/version, required semantic inputs, supported workflow classes, dimensions/aspect ratios, duration/output/audio constraints, and required prompt-guidance resources. Raw workflows and semantic-to-node mappings remain in the one adapter-owned workflow registry; profiles reference them rather than copying them.

1. Validate submitted user requirements and visible defaults before Run, including provider preference. The new cinematic Brief separates image/video sizes and total/per-shot duration under the [planned input contract](../roadmap-comfyui.md#brief-что-вводит-автор); current saved BriefV1/text inputs retain their schemas. Pin Brief and registered capability/profile versions at start; no mandatory Producer or Brief review.
2. For each required image/video job kind, filter registered profiles by fixed pipeline, all explicit requirements, effective defaulted settings, and capabilities. `comfyui provider` requires ComfyUI for both image and video here; it supplies neither workflow nor profile IDs. An explicit profile must itself pass these checks.
3. Keep a compatible explicitly requested profile. Otherwise select the compatible profile designated by the supplied defaults for that job kind/provider; if there is no designated default, select only when exactly one compatible registered profile remains. Multiple remaining choices require focused clarification or block, never arbitrary registry order or an LLM guess. A designated but missing/incompatible default is a configuration failure, not permission to substitute another profile.
4. Validate every enabled role: portrait generation, character-free background/location, sheet conditioned on both portrait and background, and multi-reference shot frames. The new Brief selects `video_mode=img2vid|ref2vid`: verify a real first-frame port for img2vid, or ordered storyboard-frame/portrait/sheet reference ports for ref2vid, without a separate background video input. A profile may bind distinct versioned workflows for these roles. Declare role→slot order, required cardinality and preprocessing in the existing workflow registry. A text-only or single-image workflow cannot replace required multi-image inputs; insufficient capacity or unmapped roles blocks before upload. No silent mode/provider/workflow substitution.

Freeze effective profile versions/digests with submitted Brief at Run. Generation tools resolve those pins without upgrading/reselecting on retry. Unavailable configuration blocks generation. Concrete defaults, workflows and live integration checks remain pending.

Declarations prove neither actual role delivery nor creative quality. Verify exact portrait+background-to-sheet binding and all required frame/video reference roles on the pinned live workflows; inspect generated results. Reference conditioning does not promise an exact first frame. Human review remains required. Validate concrete plans before provider effects under the [Render validation boundary](../tools/render.md#input-and-output-contract).

## Workflow Submission

Use the [native HTTP path](../tools/comfyui-tool.md#native-http-path). No custom webhook is configured; a separate gateway requires verified URL/auth, payload/response, status and retry semantics while preserving job ownership and ambiguous-acceptance rules. Do not invent a `/webhook` route or require a gateway. WebSocket events are progress hints, not durable completion.

Before submission the adapter must:

1. Load the pinned trusted workflow from the project workflow registry and its explicit input/output mapping. Remove only declared top-level descriptive metadata; reject other malformed entries and broken links. Every submitted graph entry must be a node with `class_type` and `inputs`. Never send a workflow file verbatim as the HTTP body.
2. Validate ordered roles/cardinality and prepare the declared graph variant before any upload. Bind all required semantic inputs to declared node fields; missing/ignored mappings are errors, not warnings. Remove unused slots and their declared exclusive branches, never required roles or shared nodes; revalidate remaining links/schemas. Resolve digest-verified managed input bytes, multipart-upload with `type=input` and `overwrite=false`, validate actual returned name/subfolder/type, and bind each role to its declared `LoadImage.inputs.image` using an input-relative path, never a Kinodel path/URL. Verify uploaded original bytes via `/view` before submit; use isolated or content-addressed names without overwriting another job's input. [Concrete binding](../tools/comfyui-tool.md#upload--конкретный-loadimage) includes empty/nonempty subfolder and current role mappings.
3. Resolve random seeds and all other effective parameters once. Persist the resolved node graph, mapping/workflow digests, used node-schema snapshots/digests, input-asset digests and upload bindings, expected output nodes, endpoint identity, and submission correlation in restricted durable job storage before `POST /prompt`. Credentials are supplied separately. Technical retry must not rerun randomization, reload an edited workflow, or discover a different output node; historical inspection must not depend on a later `/object_info` response.
4. Persist a submission-attempt intent under job ownership before the HTTP call, then persist the response/`prompt_id` before polling. A restart between these writes is ambiguous acceptance, not an unsent job. A response with `prompt_id` and `node_errors` may already have queued valid branches: record acceptance first, then block the contract failure; never classify it as definitely unsent. Review requires verified outputs from all declared nodes and successful execution status, not merely HTTP 200 or a completion flag.

Freezing a request and seed preserves request identity, not a promise of bit-identical rerendered bytes. Model/runtime/hardware behavior may differ; exact continuity uses the stored, digest-verified candidate bytes. Never substitute a rerender under an existing candidate identity.

`client_id` correlates local events; it is not a provider idempotency key. Even a server version accepting a client-supplied `prompt_id` does not by itself promise duplicate suppression. Kinodel's operation/job key deduplicates local work, not native `POST /prompt`. Reconcile a known ID against queue/history; for a lost response, use only correlation verified on the pinned server version plus the exact prepared request. An empty history/queue after restart or eviction is not proof that submission never happened. If acceptance cannot be established, keep the job blocked; another potentially charged attempt requires the explicit authorization in [runtime.md](runtime.md#rendering-extension). Never configure automatic POST retries around this boundary. On a shared server, cancellation must target the owned job using verified supported semantics; a global queue clear/interrupt is not safe job cancellation.

The [skill](../../skills/comfyui-skill/SKILL.md) and [REST reference](../../skills/comfyui-skill/references/rest-api.md) provide toolkit guidance, not project workflow selection; their legacy `render-kinodel`/backup-provider wording does not override current service ownership. `ComfyRunner.submit()` wraps a graph for HTTP but does not implement Kinodel's durable submission protocol.

Zero-reference portrait submit → matched queue/history → verified import is implemented/live-checked in 6A; fresh-process network-forbidden reopen after user-confirmed provider shutdown completes its acceptance. Reference uploads/role delivery remain 6B and batch activation 7. [ComfyUI tool](../tools/comfyui-tool.md) records native route sources; pinned-server behavior, not upstream assumptions, governs matching. Native FLOAT coercion and safe Windows subfolder handling, explicit known-ID contract revalidation and one-shot output-only recovery are defined in the [6A contract](artifacts.md#restart-safe-portrait-submission). Build acceptance lives in [Local MVP](../roadmap-mvp.md#provider-setup).

## Project Media Import

The default managed project root is `<installation>/stuff/projects/<project_id>/`, independent of cwd; an absolute `KINODEL_DATA_ROOT` overrides the data root. External reference snapshots use `inputs/`. Successful provider output is downloaded as original bytes from declared history nodes via `/view`, staged on the destination filesystem with bounded streaming, hashed/probed, and published without overwrite as `attempts/<job_id>/<candidate_id>.<digest>.<ext>`. Commit candidate identity, digest, technical metadata and job/endpoint/output-descriptor provenance only after verified publication. Provider names/subfolders never choose the local destination; temporary or invalid bytes are not visible results.

Review/save then creates approved asset identity and selected RenderResult under the [media contract](artifacts.md#candidates-and-promotion), reusing durable candidate bytes when possible. `assets/` is the target location for separately published approved media; `previews/` contains only derived files. Upload receipts and frozen graph/history evidence belong in restricted `runtime-audit/<job_id>/`. Originals remain readable through Kinodel after ComfyUI is offline. [Download/storage details](../tools/comfyui-tool.md#download--папка-проекта), [publication and crash rules](artifacts.md#managed-project-storage).

Current managed publication supports Story/Wardrobe JSON, private frozen inputs and verified portrait PNG originals. DB16/17 immutable owners remain separate from [DB18 explicit authorization/native worker](artifacts.md#restart-safe-portrait-submission). The worker proves history success before import; candidate validity alone is neither that proof nor creative approval. Reference uploads, public media reads, selection/assets and group lifecycle remain pending. Toolkit helpers do not establish Kinodel's durable ownership or validated import boundary.

## Attempt Workflow Inspection

Generation tool scope lists plan units and their attempts. Opening a workflow resolves one exact persisted job/submission attempt, not the registry's current alias. Return a sanitized read-only projection of its frozen resolved API graph, mappings, node schemas, effective parameters and verified output refs. Preserve actual string node IDs, input names and output indices; schema-defined links must not be guessed from arbitrary two-element arrays. Provider progress is observational, not a fabricated execution trace.

Editor-format `nodes/links` preserves layout but is not executable API format. Store a verified versioned editor/layout snapshot separately when available; otherwise a declared/derived display layout can show the API graph without pretending to reproduce the original editor. API JSON alone cannot recover original coordinates. The viewer uses existing React Flow drill-down, not an embedded ComfyUI editor/iframe. Save output and Kinodel verified import/selection remain separate boundaries. [UI details and acceptance](../roadmap-comfyui.md#10-генерации-внутри-tool--настоящий-workflow).
