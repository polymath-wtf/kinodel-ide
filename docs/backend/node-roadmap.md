# Нодовый продукт: план разработки

Статус: **цель принята; задачи реализации и проверки открыты.**

Пользователь должен видеть работу каждого этапа в виде нод, и затем иметь возможность собрать собственную цепочку или отредактировать текущую. Начинаем с работающего маршрута и постепенно открываем редактирование. Это дополняет [локальный MVP](../roadmap-mvp.md), а не заменяет его проверки сохранения и восстановления.

## Короткий список задач

| Этап | Задачи | Как принимаем |
|---|---|---|
| 0. Согласовать основу | [ ] Проверить минимальную архитектуру и каталог; синхронизировать новый маршрут Wardrobe и утверждения якорей | Нет двух конкурирующих владельцев промптов якорей и двух трактовок согласования |
| 1. Проверить якоря | [ ] Сохранить план; сгенерировать пример «портрет + полный рост + локация»; утвердить набор; передать его Storyboard | Один кадр использует несколько референсов с сохранением ролей; пропуск якоря блокирует выполнение |
| 2. Показать производство | [ ] Сделать нодовый просмотр готового маршрута, карточки входов/инструкций/результатов и согласования | После закрытия интерфейса видны те же задания, результаты и решения |
| 3. Открыть настройку | [ ] Разрешить версии инструкций, подключение источников и выбор поддерживаемого workflow; показать сравнение попыток | Изменение не переписывает прошлый запуск; новый платный вызов выполняется только после команды |
| 4. Собрать свою цепочку | [ ] Добавлять экземпляры известных нод; проверять порты; сохранять версию схемы; переводить её в исполняемый граф | Пользователь вставляет промежуточного агента и чанк; два экземпляра одного агента не смешивают результаты |
| 5. Расширить после проверки | [ ] Добавить ветки, сборку наборов, составные ноды и проверенное частичное переиспользование | Повторяется только разрешённая часть; старые согласования не утверждают новые результаты |

Ни один пункт этой таблицы не означает, что соответствующая проверка уже выполнена. Обязательные проверки восстановления и работы с провайдером выполняются до выпуска каждого включённого пути.

## Понятия для контекста разработки

- **Схема** — редактируемый рецепт производства; **запуск** — выполнение её зафиксированной версии.
- **Тип ноды** — возможность; **экземпляр** — конкретное место этой возможности в схеме.
- **Порт** — вход/выход с назначением и количеством материалов; **соединение** — явная зависимость.
- **Источник** — выбранная версия текста, медиа или чанка, а не самостоятельный агент.
- **План якорей** — визуальные решения и промпты; **набор якорей** — выбранные человеком изображения.
- **Кандидат** — ещё не утверждённый результат; **согласование** — решение о точной версии или наборе.
- **Попытка** — получение результата; технический повтор не меняет её входы, творческая правка создаёт новый результат.
- **Составная нода** — несколько этапов под одной карточкой, с сохранением внутренних согласований.

## Проверочный сценарий конструктора

Открыть cinematic → подключить чанк персонажа → получить и утвердить якоря → получить кадр → вставить промежуточного агента перед Storyboard → изменить его инструкции → запустить новую версию → сравнить результаты. Дополнительно: оборвать связь во время генерации и открыть приложение снова; повторная генерация и перенос старого утверждения не должны происходить незаметно.

Следующее решение пользователя: проверить [минимальную архитектуру](node-architecture.md) и [каталог](node-list.md), затем закрыть этап 0 перед реализацией.
