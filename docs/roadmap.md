# Product Roadmap

Текущая реализация и приёмка принадлежат [Local MVP](roadmap-mvp.md). Эта страница задаёт только последовательность расширений; здесь нет второго списка задач первого билда.

## Current Build Gate

Полный [cinematic MVP](pipelines/cinematic.md): пользовательский brief → история → якоря → раскадровка → видео каждого кадра → монтаж. Четыре HITL, прямые правки владельцу, сохранённые версии и восстановление запуска. Фиксированные одиночные ноды; Critic не участвует. Подробности подготовки среды и доказательства — в [плане билда](roadmap-mvp.md).

## После MVP

| Этап | Что добавляем | Когда оправдано |
|---|---|---|
| Настройка нод | Creative instructions, явный контекст, совместимые profiles | Фиксированный маршрут прошёл пользовательскую проверку |
| Последовательный конструктор | Добавление известных нод, проверка входов/выходов и HITL | Настройки и версии запуска работают предсказуемо |
| Помощь творчеству | Опциональный Critic с рекомендациями; творческий Montage | Пользователь видит пользу; рекомендации применяет только по своему выбору |
| Группы и сложные маршруты | UI-группы, затем при необходимости ветки/parallel/subgraphs | Реальные схемы стали неудобны; зависимости и recovery проверяются отдельно |
| Переиспользование | Возврат к раннему этапу новым запуском с проверенным reuse | Простого нового запуска недостаточно; старые approvals не переносятся на изменённое |
| Память и другие pipelines | Craft, reviewed chunks/wiki; музыка и сериалы | После рабочего cinematic, без обязательной публикации памяти на каждом финале |
| Hosted profile | PostgreSQL, аккаунты, приватное хранилище, учёт сервисных затрат | Отдельные concurrency/auth/storage/billing проверки до включения |

Конструктор не ждёт второго pipeline; общие graph builders извлекаются только при реальном повторении. Поиск начинается с прямого выбора/FTS, embeddings — после измеримого выигрыша. Streaming, автоматические backups, расширенная упаковка/обновление и operational metrics включаются по потребности.

## Отдельные будущие обязательства

Hosted pricing/retention/auth decisions остаются в [database contracts](database/README.md) и [credits/storage](database/credits-billing.md); они не являются локальными MVP-задачами. Перед внешней production-эксплуатацией нужны проверенные backups/restore, ограничения расходов и эксплуатационные процедуры. Произвольный код в графах, универсальный plugin/compiler framework и автономные swarms не запланированы без конкретного сценария.
