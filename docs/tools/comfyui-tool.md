# ComfyUI Tool: workflow и REST-путь

Статус: **подготовка adapter; mappings прочитаны из API-format JSON, сервер и генерация не проверены**. Это транспорт и кандидаты workflow для [Render](render.md), не зарегистрированные/проверенные production profiles. Рендер принадлежит worker, а не агенту или HTTP-запросу пользователя; кандидаты становятся `anchor_frames`, `story_frames` и `shot_videos` только после review/selection. [Контракт provider и crash/retry](../backend/comfyui.md) остаётся обязательным.

## Текущие файлы и порты

Пути ниже относительно корня репозитория, номера — **точные node IDs только указанных версий**. В registry при реализации закрепить файл + digest и одну запись mapping на workflow; при замене JSON перепроверить все IDs, типы и связи. Поля промптов не унифицировать на уровне ComfyUI: унифицируется семантический запрос Kinodel, а запись в ноду зависит от workflow.

| Кандидат / файл в `workflow/comfyui/` | Семантические входы → `node.inputs.field` | Объявленный output |
|---|---|---|
| `krea2-txt2img` — `txt2img krea2 api v1_local.json` | `prompt` → `864.text` (`CLIPTextEncode`); `width` → `815.value`, `height` → `814.value` (`easy int`); при управляемом seed → `856.seed` | `865` `SaveImage`, `images` (ожидается PNG) |
| `krea2-img2img` — `img2img krea2 v1.4_local.json` | `prompt` → `876.prompt` (`Krea2EditGroundedEncode`); `source_image` → `880.image` (`LoadImage`); `width` → `815.value`, `height` → `814.value`; seed → `856.seed` | `881` `SaveImage`, `images` |
| `qwen21-img2img` — `qwen img2img api v1.json` | `prompt` → `459_474.prompt` (`TextEncodeQwenImage21`); `source_image` → `470.image` (`LoadImage`); `width` → `485.value`, `height` → `484.value`; seed → `459_458.seed` | `494` `SaveImage`, `images` |
| `minimax-h3-img2vid` — `minimax img2vid api v1.json` | `prompt` → `136.prompt`; `source_image` → `160.image` (`LoadImage`); `width` → `152.Number`, `height` → `153.Number` (`Int`, значения в файле — строки); `duration_seconds` → `132.value` (`PrimitiveFloat`, «Float (Duration in sec)»); seed → `129.noise_seed` | `157` `VHS_VideoCombine`, `format=video/h264-mp4`, `save_output=true` |
| `minimax-h3-ref2vid` — `minimax ref2vid api v1.json` | Как у `img2vid`: `136.prompt`, `152.Number`, `153.Number`, `132.value`, `129.noise_seed`; три изображения: `ref1` → `160.image`, `ref2` → `159.image`, `ref3` → `161.image` | `157` `VHS_VideoCombine`, `format=video/h264-mp4`, `save_output=true` |

`width base`/`height base` — названия нод в `_meta`, а не ключи API. Размеры Krea/Qwen идут через `easy int.value`; MiniMax — через `Int.Number`. Video `136.length` связан с `131` (`ComfyMathExpression`) от `132.value`: секунды **не** записываются в `136.length` напрямую. В JSON выражение `max(5, round(a * 24)) + (5 - (max(5, round(a * 24)) % 17)) % 17` рассчитывает число кадров; после `158` RIFE ×2 и `157.frame_rate=30` измеренная длительность MP4 может отличаться от введённых секунд. Проверить допуск и `ffprobe` на сервере, не обещать точное число секунд из одного поля.

Оба `img2img` используют один `LoadImage`, но Krea передаёт resized source в grounded encoder **и** source patch/VAE, Qwen — в `TextEncodeQwenImage21.images.image_1`. Внутренние sampler/encode/model paths различаются; выбор workflow делается по закреплённому совместимому image profile, не по имени `KSampler`. У Qwen нода `495` (`Power Lora Loader (rgthree)`) содержит `PowerLoraLoaderHeaderWidget` и пустой `➕ Add Lora`: header не является путём LoRA. У Krea нода `819.inputs.lora_1.lora` уже содержит путь к identity LoRA. Оставить model/LoRA параметры закреплёнными в файлах до проверки node schema и осознанного включения их в профиль; не принимать произвольные пути от агента.

У `img2vid` в `136` объявлен **один** `ref_images.ref_image_0` из `160` через resize `149`; у `ref2vid` три отдельных `ref_images.ref_image_0/_1/_2` из `160/159/161` через resize `149/150/162`. Заголовки нод `Load Image ref1/2/3` не заменяют явного mapping ролей. Оба графа используют `MiniMaxH3ReferenceToVideo`, а не подтверждённый специальный start-frame input. Выход `157` получает кадры после RIFE и также подключённое аудио от `121`; для silent cinematic надо проверить удаление audio stream на импорте/монтаже. В `img2vid` LoRA `145` есть в JSON, но не подключена к цепи model `127 → 156 → 155`: не считать её активной; у `ref2vid` подключена через `145 → 156`.

## Как использовать в cinematic

| Этап | Привязка к кандидатам | Условие включения |
|---|---|---|
| `anchor-gen` | Два вызова `krea2-txt2img` для portrait и character-free location; `krea2-img2img` **или** `qwen21-img2img` для sheet с точным portrait | Зафиксировать профиль и загрузить именно результат portrait в sheet. Location независима. Число 2+1 — первый пример, не ограничение схемы. |
| `frames-gen` | По одному изображению на каждый shot с сохранением семантических ролей portrait/sheet/location | **Блокировано текущими image JSON**, если плану нужны три одновременных reference images: оба `img2img` сейчас имеют только один фактический вход. Нужен реально проверенный multi-reference image workflow с отдельными портами для всех обязательных ролей; не склеивать три картинки и не выкидывать роли молча. |
| `video-gen` | `minimax-h3-img2vid` с выбранным storyboard frame для каждого shot | Живой тест должен подтвердить, что кадр действительно является точным началом действия/видео. По JSON доказано только reference conditioning. Без такого доказательства контракт MVP `i2v` не выполнен. |
| Эксперимент | `minimax-h3-ref2vid`: сначала ref1=portrait, ref2=sheet, ref3=location; отдельно испытать storyboard frame + две утверждённые anchors с явным указанием выбранных ролей | Это альтернативное reference conditioning, **не** подмена обязательного start frame. Сравнить на одном shot continuity, начало видео и фактические размеры/длительность. Все три входа обязательны только в профиле, который требует их; в candidate JSON они подключены. |

Выбор между Krea/Qwen (и видео-режимами после проверки) — deterministic pinned profile по [правилу отбора](../backend/comfyui.md#profile-selection). Профиль может связывать разные workflow с portrait/sheet/location/shot, но неподдержанная роль или несовместимые размеры/длительность блокируют submit. Попытки не утверждаются автоматически, и отсутствие способности к multi-reference нельзя исправить промптом.

## Native HTTP path: только upload, без URL для LoadImage

Для локального сервера базовый адрес обычно `http://127.0.0.1:8188` без `/api`; endpoint/auth — trusted config. Kinodel не устанавливает и не запускает внешний ComfyUI. Удалённый native endpoint допустим лишь с проверенными auth/routes; Cloud использует `/api/*`, `X-API-Key` и `/api/history_v2/{id}`, это отдельный transport, не Runpod Serverless job API.

1. **Preflight:** `GET /system_stats`, `GET /object_info` (нужные classes и input schemas), проверка моделей и точных связей graph. Health сам по себе не доказывает выполнение. Загружать только доверенный API-format JSON: верхний объект `node_id → {class_type, inputs, ...}`; убрать только объявленную описательную `_meta`, не editor-format `nodes/links` и не весь файл в тело запроса.
2. **Подготовка:** проверить конкретный план, все обязательные роли/число входов и права на exact media refs **до первого upload**. Сохранить snapshot workflow+mapping digest, resolved params/seed, input digests и expected output node в restricted job storage. Изображения отправлять multipart `POST /upload/image` с полем `image` (содержимое файла, например `curl -F "image=@portrait.png" -F "type=input"`, с уникальным именем для данного digest/job); не использовать перезапись чужого файла. Ответ вроде `{"name":"<unique>.png","subfolder":"","type":"input"}` привязать к job, проверить имя/подпапку; `LoadImage.inputs.image` должен ссылаться на загруженный серверный input (способ кодирования непустого `subfolder` проверить на pinned server). **Не** подставлять URL, локальный путь Kinodel или исходное имя из fixture JSON. Для нескольких refs загрузить и привязать каждую роль отдельно.
3. **Submit:** сохранить intent до сетевого эффекта; `POST /prompt` c `{"prompt": <resolved graph>, "client_id": "<persisted uuid>"}`. После ответа записать `prompt_id`; ненулевые `node_errors`/ошибку валидации считать отказом. `client_id` не idempotency key. При пропаже ответа сверять собственную корреляцию с `/queue`/`/history` на проверенной версии либо блокировать неизвестный исход; **не делать слепой повторный POST**. Upload-bindings и payload повторного разрешённого вызова должны быть теми же.
4. **Ожидание/импорт:** polling `GET /queue` и `GET /history/{prompt_id}` (WebSocket опционален). В history проверять `status.status_str == "success"` и отсутствие `execution_error` — `completed=true` бывает и при ошибке. Читать **только** output объявленной ноды (`865`, `881`, `494` либо `157`) и фактически возвращённые filename/subfolder/type; скачать `GET /view?filename=...&subfolder=...&type=...` с корректным URL-encoding и `type` из проверенного output. Для VHS не предполагать имя поля history (`gifs`/`videos`/`video`) без проверки установленной версии. Проверить media bytes/MIME, размеры, длительность и audio stream, затем импортировать как immutable candidate с provenance. Путь на сервере — не `AssetRef`.

Глобальные `/interrupt` и clear queue нельзя использовать для адресного cancel на общем сервере. Поздний результат после cancel не продвигается в selected result. Подробный протокол неоднозначного принятия, retry и сохранения payload — [backend ComfyUI](../backend/comfyui.md#workflow-submission).

## Следующая проверка на работающем сервере

Выполнить по одному REST-проходу для каждого кандидата: `object_info`/models → upload portrait (и три разных refs для ref2vid) → подготовленный `POST /prompt` → queue/history → `/view` → digest/ffprobe; сохранить request/response/status fixtures и версии установленного ComfyUI/custom nodes. Отдельно визуально проверить portrait→sheet, три роли в frame workflow (когда он появится), стартовый storyboard frame→первый кадр клипа, долю кадра после RIFE и политику silent montage. Провести пробу lost response/restart перед включением worker. Ни одно из этих испытаний этой документацией не выполнено; [приёмка и очередность](../roadmap-mvp.md#provider-setup).
