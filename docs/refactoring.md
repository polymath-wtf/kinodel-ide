# Legacy Research

`legacy/` is read-only evidence from the previous Kinodel prototype. Use it only when a current contract leaves a concrete product or craft question unanswered.

## What To Extract

- Agent craft, quality criteria and useful examples.
- Proven provider/tool behavior and media workflow requirements.
- Product intent for music, serial and other later pipelines.
- Failure cases that justify a current invariant or acceptance check.

## What Not To Carry Forward

- Hermes routing, `/goal` commands, text handoff envelopes or file-backed state machines.
- Legacy schemas, status files, provider defaults or automatic approvals.
- Generic abstractions without a second current use case.
- Claims that are already resolved by current domain contracts.

Reduce any retained finding into the smallest relevant page under `docs/agents/`, `docs/pipelines/`, `docs/tools/` or another owning domain. Do not create a second historical summary: unresolved activation questions belong in [future topics](features/future.md), and first-build work belongs only in [Local MVP](roadmap-mvp.md).
