# 🌌 Gemini Embedding 2 preview: Руководство Разработчика

**Gemini Embedding 2 preview** (идентификатор API: `gemini-embedding-2-preview`) — это унифицированная мультимодальная модель эмбеддингов следующего поколения от Google, представленная в марте 2026 года. В отличие от традиционных текстовых энкодеров, эта модель отображает текст, изображения, аудио, видео и PDF-документы в **единое векторное пространство**.

Это означает, что вы можете выполнить текстовый запрос и найти релевантный график, отсканированный счет-фактуру или видеоинструкцию с помощью стандартного поиска по косинусному сходству (cosine similarity).

## 2. Matryoshka Representation Learning (MRL)

Одной из самых мощных функций Gemini Embedding 2 является **Matryoshka Representation Learning (MRL)**. 

Исторически, размерность эмбеддинга (например, 3072) фиксировалась. Если ваша база данных (например, Pinecone, Chroma) испытывала проблемы с памятью или задержками, вам приходилось использовать другую модель (с размерностью 768) и пересчитывать *всю* базу с нуля.

MRL решает эту проблему. Подобно русской матрешке, где маленькая кукла спрятана внутри большой, MRL обучает модель вкладывать важнейшие семантические концепции в **самые первые компоненты вектора**.

### 🧮 Как это работает (Математика)

Пусть модель извлекает из входных данных представление $z \in \mathbb{R}^d$, где базовая размерность $d=3072$. При стандартном обучении функция потерь $\mathcal{L}$ оценивает только полный вектор. 

При использовании MRL, модель параллельно оптимизирует несколько усеченных версий вектора $z$. Пусть набор целевых размерностей — это $\mathcal{M} = \{m_1, m_2, \dots, m_k\}$, где $m_1 < m_2 < \dots < d$. Модифицированная функция потерь выглядит так:

$$\mathcal{L}_{MRL}(x)=\sum_{m \in \mathcal{M}} w_m \cdot \mathcal{L}(z_{1:m}, y)$$

Где $z_{1:m}$ — срез из первых $m$ измерений вектора, $w_m$ — весовой коэффициент, а $y$ — целевое значение. Из-за того, что градиентный спуск штрафует модель за ошибки даже на малых срезах (например, при $m=256$), модель вынуждена «сжимать» самую критичную информацию в начало вектора.

### 💡 Преимущества MRL
* **Экономия памяти до 12 раз**: Использование векторов размерности 256 вместо 3072 экономит до 91.6% места в векторной БД.
* **Снижение затрат**: Меньше оперативной памяти (RAM) для хранения индексов в HNSW/IVF графах.
* **Отсутствие падения качества**: Срез до 768 измерений сохраняет более ~98% точности оригинального вектора в задачах MTEB.
* **Обратная совместимость**: Вы можете просто сделать срез массива `vector[:256]` в коде — и он будет работать! 

*(В API Gemini это реализовано через параметр `output_dimensionality`)*.

## 3. Мультимодальное Векторное Пространство

Модель отображает все типы данных в одно координатное пространство:

1. **Кросс-модальный поиск**: Вы можете вычислить `cosine_similarity(text_vector, image_vector)`.
2. **Нулевой индекс (Zero-shot OCR)**: Загрузите скан страницы (PDF) или диаграмму, и она будет найдена по текстовому вопросу *"какова выручка за Q3?"*.
3. **Видео-семантика**: При передаче видео (MP4) модель анализирует как визуальный ряд, так и звуковую дорожку для создания единого эмбеддинга.

## 4. Типы Задач (Task Types)

Gemini Embedding 2 — это **Task-Aware** модель. Она динамически адаптирует внутренние веса в зависимости от того, зачем вам нужен вектор. Обязательно указывайте `task_type` в ваших запросах.

| `task_type` | Когда использовать? | Описание |
| :--- | :--- | :--- |
| `RETRIEVAL_DOCUMENT` | При индексации БД | Используется для векторизации базы знаний (ваших документов, файлов, картинок), по которым будет идти поиск. |
| `RETRIEVAL_QUERY` | При поиске пользователем | Используется в рантайме для векторизации *запроса* пользователя (например, "Как настроить сервер?"). |
| `SEMANTIC_SIMILARITY` | Оценка сходства | Для измерения того, насколько два текста/изображения похожи (например, A/B тесты, поиск дубликатов). |
| `CLASSIFICATION` | Машинное обучение | Вектор будет передан в классификатор (например, SVM, Random Forest) или нейросеть. |
| `CLUSTERING` | Кластеризация | Для алгоритмов вроде K-Means или DBSCAN. Оптимизирует разброс точек в пространстве. |

> **⚠️ Важное правило RAG:** Базу индексируйте с `RETRIEVAL_DOCUMENT`. А строку поиска от пользователя векторизуйте с `RETRIEVAL_QUERY`. Не путайте их местами!

## 5. Практические Примеры (API & Код)

### 🐍 Python (Google AI Studio / SDK)

Для работы потребуется пакет `google-generativeai`:
```bash
pip install -U google-generativeai
```

**Пример 1: Текстовый RAG и использование MRL (Срез до 256)**

```python
import google.generativeai as genai
import os

genai.configure(api_key=os.environ["GEMINI_API_KEY"])

# Векторизация базы знаний (Документ)
doc_result = genai.embed_content(
    model="models/gemini-embedding-2-preview",
    content="Инструкция: для сброса пароля перейдите в настройки безопасности и нажмите 'Сброс'.",
    task_type="RETRIEVAL_DOCUMENT",
    title="Сброс пароля", # title полезен для повышения качества эмбеддинга
    output_dimensionality=256 # <-- Магия Matryoshka
)

# Векторизация поискового запроса пользователя
query_result = genai.embed_content(
    model="models/gemini-embedding-2-preview",
    content="Как поменять пароль?",
    task_type="RETRIEVAL_QUERY",
    output_dimensionality=256 # Обязательно должна совпадать с базой!
)

print(f"Размерность документа: {len(doc_result['embedding'])}") # 256
print(f"Размерность запроса: {len(query_result['embedding'])}") # 256
```

**Пример 2: Мультимодальный эмбеддинг (Изображение)**

При работе через Vertex AI или последние версии AI Studio вы можете передавать файлы.

```python
import google.generativeai as genai
from PIL import Image

image_path = "architecture_diagram.png"
img = Image.open(image_path)

response = genai.embed_content(
    model="models/gemini-embedding-2-preview",
    content=[img, "Диаграмма архитектуры микросервисов, бэкенд на Python"],
    task_type="RETRIEVAL_DOCUMENT",
    output_dimensionality=768
)

vector = response['embedding']
```

### 🌐 Node.js (JavaScript)

```javascript
import { GoogleGenerativeAI } from "@google/generative-ai";

const genAI = new GoogleGenerativeAI(process.env.API_KEY);
const model = genAI.getGenerativeModel({ model: "gemini-embedding-2-preview" });

async function run() {
  const text = "Основы квантовой физики и принцип суперпозиции.";
  const result = await model.embedContent({
    content: text,
    taskType: "RETRIEVAL_DOCUMENT",
    outputDimensionality: 768, // MRL
  });
  
  console.log("Vector:", result.embedding.values);
}

run();
```

## 6. Рекомендации по Чанкингу и RAG

Контекстное окно модели составляет 8,192 токенов. Однако, заталкивать весь 8k-текст в один эмбеддинг — плохая практика для RAG (снижается плотность информации). 

**Золотые стандарты для `gemini-embedding-2`:**

1. **Размер чанка (Chunk Size):** 512 – 1024 токенов.
   * *Для плотного технического текста/кода:* 400 – 600 токенов.
   * *Для художественного текста:* 1000 – 1200 токенов.
2. **Перекрытие (Overlap):** 10 – 15% (примерно 50-100 токенов), чтобы не терять контекст на стыках.
3. **Метаданные:** Поскольку модель мультимодальная, обязательно прикрепляйте метаданные к векторам в вашей БД (Chroma/Pinecone).
   * *Для текста:* `type=text`, `source_url`, `author`.
   * *Для видео:* `type=video`, `start_sec`, `end_sec`.
   * *Для PDF:* `type=pdf_scan`, `page_number`.
